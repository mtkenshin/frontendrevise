# Front-End Developer Interview Questions: HTML

1. **What is semantic HTML, and why is it important?**
   * **Answer:** Semantic HTML uses elements that clearly describe their meaning to both the browser and the developer (e.g., `<header>`, `<main>`, `<article>`, `<footer>`). 
   * **Why it matters:** It improves accessibility (screen readers navigate via semantic landmarks), boosts SEO (search engines better understand content hierarchy), and makes code easier to read and maintain.

2. **Explain the difference between `<div>` and `<section>`.**
   * **`<div>`:** A generic, non-semantic block container used purely for styling or grouping elements without adding structural meaning.
   * **`<section>`:** A semantic element representing a standalone, logical grouping of content (typically with a heading) that forms part of a broader document outline.

3. **What are the differences between block-level and inline elements?**
   * **Block-level elements** (e.g., `<div>`, `<p>`, `<h1>`): Occupy 100% of the container's width, start on a new line, and respect top/bottom margins and padding.
   * **Inline elements** (e.g., `<span>`, `<a>`, `<strong>`): Occupy only as much width as their content requires, do not start on a new line, and ignore top/bottom margins and height properties.

4. **How do you ensure a webpage is accessible using HTML?**
   * Use semantic structural tags (`<nav>`, `<main>`, `<article>`).
   * Pair inputs with explicit `<label>` elements using the `for` attribute.
   * Provide descriptive `alt` text for non-decorative images.
   * Implement ARIA roles, states, and properties (`aria-expanded`, `aria-label`) when native HTML falls short.
   * Maintain a logical document outline using proper heading hierarchy (`<h1>` through `<h6>`).

5. **What is the purpose of the `alt` attribute in `<img>` tags?**
   * **Accessibility:** Provides text alternatives for assistive technology (e.g., screen readers) used by visually impaired users.
   * **Fallback:** Displays text if the image fails to load due to network issues or broken paths.
   * **SEO:** Helps search engine crawlers index the image context correctly.

6. **What is the difference between the `id` and `class` attributes?**
   * **`id`:** Must be unique per page; targets a single element. Carries high CSS specificity and acts as an anchor target.
   * **`class`:** Non-unique; can be reused across multiple elements. Carries standard specificity and is ideal for reusable styles.

7. **What are data attributes, and how are they used in HTML?**
   * **Definition:** Custom attributes prefixed with `data-*` (e.g., `data-user-id="123"`) used to embed private custom data on standard HTML elements.
   * **Usage:** Easily accessed in JavaScript via `element.dataset` or styled in CSS using attribute selectors (`[data-active="true"]`). Useful for UI state tracking and passing lightweight server data to scripts.

8. **What is the purpose of the `<meta>` tag? Can you give examples of its use?**
   * **Purpose:** Provides machine-readable metadata about the HTML document (character set, viewport instructions, author, search engine directives).
   * **Examples:**
     ```html
     <meta charset="UTF-8">
     <meta name="viewport" content="width=device-width, initial-scale=1.0">
     <meta name="description" content="A brief summary of the web page context for SEO.">
     ```

9. **How does the `<form>` element work, and what are some best practices for creating forms?**
   * **Mechanism:** Collects input data and sends it to a server endpoint via specified methods (`GET`, `POST`).
   * **Best Practices:**
     * Always pair controls with `<label>` tags.
     * Set appropriate `type` attributes (`email`, `number`, `tel`) to trigger optimal mobile keyboards.
     * Utilize native validation attributes (`required`, `pattern`, `min`, `max`).
     * Group related fields using `<fieldset>` and `<legend>`.

10. **What is the difference between an absolute and a relative URL in HTML?**
    * **Absolute URL:** Specifies the complete web address including domain and protocol (e.g., `https://example.com/assets/logo.png`).
    * **Relative URL:** Specifies a path relative to the current file location or site root (e.g., `../assets/logo.png` or `/assets/logo.png`).

# Front-End Developer Interview Questions: CSS

1. **What is the difference between relative, absolute, fixed, and sticky positioning in CSS?**
   * **`relative`:** Offset relative to its normal position in the document flow without affecting surrounding elements.
   * **`absolute`:** Positioned relative to its nearest non-static ancestor; removed from the normal document flow.
   * **`fixed`:** Positioned relative to the browser viewport; remains stationary during page scrolling.
   * **`sticky`:** Toggles between `relative` and `fixed` depending on the user's scroll position relative to a defined threshold.

2. **What are CSS pseudo-classes, and how are they different from pseudo-elements? Provide examples.**
   * **Pseudo-classes (`:`)**: Target special states of an element (e.g., `:hover`, `:focus`, `:nth-child(2)`).
   * **Pseudo-elements (`::`)**: Style specific sub-parts of an element or inject dynamic structural elements (e.g., `::before`, `::after`, `::first-line`).

3. **Explain the difference between `em`, `rem`, `%`, and `px` units in CSS.**
   * **`px`:** Absolute length unit; static across all dynamic root changes.
   * **`em`:** Relative unit scaled based on the element's direct or inherited `font-size`.
   * **`rem`:** Relative unit scaled strictly based on the root (`<html>`) element's `font-size`.
   * **`%`:** Relative unit scaled based on the parent container's dimension for the given property.

4. **What is the CSS box model, and what are its components?**
   * Consists of four layer boundaries wrapping an HTML element: **Content** $\rightarrow$ **Padding** $\rightarrow$ **Border** $\rightarrow$ **Margin**.
   * **`box-sizing` impact:** Default `content-box` adds padding and border to the defined width/height. Setting `box-sizing: border-box` forces defined dimensions to absorb padding and border sizes.

5. **How does flexbox differ from CSS grid? When would you use each?**
   * **Flexbox:** 1-Dimensional layout system (handles rows *or* columns). Best for components, navigation bars, and dynamic content alignment.
   * **CSS Grid:** 2-Dimensional layout system (handles rows *and* columns simultaneously). Best for overall page structure, complex page layouts, and strict multi-column grids.

6. **What are media queries, and how do you use them?**
   * **Definition:** CSS techniques used to apply conditional style rules based on device characteristics (screen width, orientation, resolution).
   * **Syntax Example:**
     ```css
     @media (max-width: 768px) {
       .container {
         flex-direction: column;
       }
     }
     ```

7. **What is the difference between inline, inline-block, and block elements in CSS?**
   * **`inline`:** Flows horizontally within text; ignores `width`, `height`, and vertical margins/padding.
   * **`block`:** Forces a line break; spans 100% of parent width; honors all box model dimensions.
   * **`inline-block`:** Flows horizontally inline with surrounding elements, but accepts custom `width`, `height`, and margins.

8. **How do you optimize CSS for performance?**
   * Minify stylesheet payloads and combine critical paths.
   * Avoid overly deep or complex non-prefixed CSS selectors.
   * Utilize `will-change` hardware acceleration carefully for animations.
   * Remove unused CSS through tree-shaking toolchains (PurgeCSS).
   * Use modern CSS properties over costly JS layout manipulations.

9. **What are the differences between relative, absolute, and fixed lengths in CSS properties?**
   * **Relative lengths** (`em`, `rem`, `vw`, `%`): Dynamically re-scale depending on dynamic variables like parent sizes or viewport dimensions.
   * **Absolute lengths** (`px`, `cm`, `pt`): Fixed physical sizes that remain constant regardless of container changes.

10. **How would you create a responsive design for a multi-column layout?**
    * Combine CSS Grid (`grid-template-columns: repeat(auto-fit, minmax(300px, 1fr))`) or Flexbox with `flex-wrap: wrap`.
    * Use CSS media queries to explicitly drop total columns on targeted small viewports.

# Front-End Developer Interview Questions: JavaScript

1. **What is the difference between `var`, `let`, and `const` in JavaScript?**
   * **`var`:** Function-scoped, hoisted (initialized as `undefined`), and re-declarable.
   * **`let`:** Block-scoped, hoisted to Temporal Dead Zone (TDZ), re-assignable.
   * **`const`:** Block-scoped, hoisted to TDZ, requires immediate initialization, cannot be reassigned (though internal object properties remain mutable).

2. **Explain the concept of closures in JavaScript.**
   * A closure is a function's ability to retain access to variables from its outer lexical scope, even after that outer scope function has finished executing. 
   * Common use cases include private state encapsulation and function currying.

3. **What is the difference between `==` and `===` in JavaScript?**
   * **`==` (Abstract Equality):** Compares values after attempting dynamic implicit type coercion (e.g., `'0' == 0` evaluates to `true`).
   * **`===` (Strict Equality):** Compares both value and data type directly without performing coercion (e.g., `'0' === 0` evaluates to `false`).

4. **What are JavaScript promises, and how do they work?**
   * An object representing the eventual completion (or failure) of an asynchronous operation and its resulting value.
   * Possesses 3 mutually exclusive states: `pending`, `fulfilled`, or `rejected`. Handled using `.then()`, `.catch()`, or `async/await`.

5. **What is the difference between `call()`, `apply()`, and `bind()` in JavaScript?**
   * **`call(thisArg, arg1, arg2)`:** Invokes the target function immediately with explicit `this` binding and arguments passed individually.
   * **`apply(thisArg, [argsArray])`:** Invokes the target function immediately with explicit `this` binding and arguments passed as an array.
   * **`bind(thisArg, arg1, arg2)`:** Returns a brand-new function instance with permanently bound `this` context for later invocation.

6. **What are higher-order functions in JavaScript?**
   * Functions that accept other functions as arguments, return functions, or both.
   * Native examples include Array prototype methods like `.map()`, `.filter()`, and `.reduce()`.

7. **What is the difference between `null` and `undefined` in JavaScript?**
   * **`undefined`:** Default state of a declared variable that has not yet been assigned a value, or missing return values.
   * **`null`:** Explicit assignment indicating an intentional, empty non-value placeholder.

8. **How does event delegation work in JavaScript?**
   * Leverages event propagation (bubbling phase) to manage event listeners efficiently. Instead of attaching handlers to dozens of child nodes, a single listener is placed on a parent container to catch events originating from children via `event.target`.

9. **What is the difference between synchronous and asynchronous JavaScript?**
   * **Synchronous:** Single-threaded sequential execution; each task blocks subsequent operations until completed.
   * **Asynchronous:** Offloads long-running tasks (network requests, timers) to browser APIs outside the main thread, handling responses via callbacks, Promises, or event loop queues without blocking rendering.

10. **What are JavaScript modules, and why are they important?**
    * Modular architecture format (`import`/`export`) that organizes isolated snippets of code into reusable files. They eliminate global namespace pollution, ensure maintainable dependency graphs, and enable dead-code elimination (tree shaking).

# Front-End Developer Interview Questions: React

1. **What is React, and how does it differ from traditional JavaScript frameworks?**
   * React is a component-driven UI library (not a full-featured framework) focusing on the view layer.
   * Uses declarative code syntax, unidirectional data flow, and a virtual DOM, whereas traditional frameworks often rely on two-way data binding and direct DOM manipulation.

2. **What are React hooks, and why are they used?**
   * Functions allowing functional components to hook into React state, lifecycle updates, and side effects without writing legacy class components (e.g., `useState`, `useEffect`, `useReducer`).

3. **What is the virtual DOM, and how does React use it?**
   * A lightweight in-memory JSON representation of the actual DOM. React generates new virtual tree snapshots upon state updates, runs a reconciliation ("diffing") algorithm against previous snapshots, and batches target changes efficiently to minimize costly browser paints.

4. **What are React props, and how are they different from state?**
   * **Props:** Read-only inputs passed from parent components down to child components (immutable context).
   * **State:** Local component instance variables managed internally that trigger component re-renders when mutated via state updater functions.

5. **What is JSX, and how does it work in React?**
   * A syntax extension for JS that lets developers write HTML-like markup directly inside script files. Tooling compilers like Babel transpile JSX elements into `React.createElement()` function calls.

6. **Explain the difference between controlled and uncontrolled components in React.**
   * **Controlled:** Component UI state and input value are driven entirely by explicit React state (`value` property attached to `onChange` dispatcher).
   * **Uncontrolled:** Component input value relies directly on native DOM node management, accessed via React references (`useRef`).

7. **What is React’s Context API, and when would you use it?**
   * Native mechanism for broad state broadcasting through component hierarchies without manually passing props down through nested children ("prop-drilling"). Ideal for low-frequency global values like theme colors or authenticated user details.

8. **What is the purpose of `key` props in React, and why are they important?**
   * Unique identifiers used by the diffing engine to track list item insertions, mutations, or deletions. Omitting stable key props forces inefficient full list re-renders and causes state leakage across sibling elements.

9. **What are React lifecycle methods? Provide examples of their use cases.**
   * Hooks or methods executing at specific phases of a component (Mounting, Updating, Unmounting). In modern React, `useEffect` abstracts lifecycle phases:
     ```javascript
     // Mount/Unmount equivalent
     useEffect(() => {
       const sub = subscribe();
       return () => sub.unsubscribe(); // Unmount cleanup
     }, []);
     ```

10. **How would you handle performance optimization in a large React application?**
    * Implement code-splitting using `React.lazy` and `Suspense`.
    * Prevent expensive recalculations using `useMemo` and standard function recreation using `useCallback`.
    * Wrap structural tree pure components in `React.memo`.
    * Virtualize long dynamic list renders using libraries like `react-window`.

# Front-End Developer Interview Questions: Angular

1. **What is Angular, and how does it differ from other frontend frameworks?**
   * A full-fledged, opinionated TypeScript framework provided out-of-the-box with routing, HTTP clients, form management, and testing utilities. Uses dependency injection and strict modular patterns, contrasting with component libraries like React.

2. **What is the Angular lifecycle, and why is it important?**
   * Sequential events tracking component life from creation through deletion. Key hooks include:
     * `ngOnInit`: Executes initialization parameters after data-bound inputs resolve.
     * `ngOnChanges`: Fires whenever input binding values shift.
     * `ngOnDestroy`: Handles cleanup routines prior to component disposal.

3. **Explain the difference between `@Input()` and `@Output()` decorators in Angular.**
   * **`@Input()`:** Decorator marking a property as callable by a parent component to pass data downstream.
   * **`@Output()`:** Decorator binding an `EventEmitter` instance to pass data upstream to parents via event handling.

4. **What is Angular’s dependency injection system, and how does it work?**
   * A structural pattern where class dependencies (e.g., services) are instantiated and supplied by Angular's runtime framework rather than explicitly instantiated manually inside target components. Uses `@Injectable()` decorators.

5. **What is the purpose of Angular modules, and how are they structured?**
   * **NgModule:** Contextual containers organizing cohesive application blocks. Defined by `@NgModule`:
     * `declarations`: Components, directives, and pipes belonging to the module.
     * `imports`: External modules required by templates within this module.
     * `providers`: Services available for dependency injection.
     * `exports`: Declarations exposed to importing modules.

6. **What are Angular directives, and what are the differences between structural and attribute directives?**
   * **Structural Directives (`*ngIf`, `*ngFor`):** Alter actual layout DOM structure by dynamically instantiating or destroying HTML elements.
   * **Attribute Directives (`ngClass`, `ngStyle`):** Change appearance, class properties, or behaviors of existing DOM elements without altering tree architecture.

7. **What are Angular pipes, and when would you use them?**
   * Pure dynamic functions declared inside templates (`|`) to format output parameters (e.g., currency, dates, string transformations) without mutating underlying raw variable models.

8. **How does Angular handle forms, and what is the difference between template-driven and reactive forms?**
   * **Template-Driven:** Simple forms defined entirely within HTML markup using implicit directives like `ngModel`.
   * **Reactive Forms:** Programmatic, explicit form models configured in TypeScript using `FormGroup` and `FormControl`. Offers predictable immutable state streams and synchronous dynamic validations.

9. **What is the Angular Router, and how does it handle navigation?**
   * Enables single-page navigation across states by mapping browser paths to target component views via structural array definitions. Intercepts navigation using Route Guards (`CanActivate`).

10. **What strategies would you use to optimize an Angular application’s performance?**
    * Switch component strategies to `ChangeDetectionStrategy.OnPush`.
    * Configure lazy-loaded feature modules.
    * Utilize `trackBy` functions with structural `*ngFor` loops.
    * Build projects using Ahead-of-Time (AoT) compilation.

### Algorithmic Challenges

#### 1. Array Deduplication

// Function removing duplicate elements while preserving initial item order
const removeDuplicates = (arr) => [...new Set(arr)];

// removeDuplicates([1, 2, 2, 3, 4, 4, 5]) -> [1, 2, 3, 4, 5]

#### 2. Two Sum Problem
```javascript

const twoSum = (nums, target) => {
  const map = new Map();
  for (let i = 0; i < nums.length; i++) {
    const complement = target - nums[i];
    if (map.has(complement)) {
      return [map.get(complement), i];
    }
    map.set(nums[i], i);
  }
  return [];
};

// Example Usage:
// twoSum([2, 7, 11, 15], 9) -> [0, 1]
```

#### 3. Reversing a String

```javascript
const reverseString = (str) => {
  let reversed = '';
  for (let i = str.length - 1; i >= 0; i--) {
    reversed += str[i];
  }
  return reversed;
};

// Example Usage:
// reverseString("frontend") -> "dnetnorf"

```

#### 4. Check for a palindrome

```javascript
const isPalindrome = (str) => {
  const cleaned = str.toLowerCase().replace(/[^a-z0-0]/g, '');
  return cleaned === cleaned.split('').reverse().join('');
};

// Example Usage:
// isPalindrome("radar") -> true
```

    * Modular architecture format (`import`/`export`) that organizes isolated snippets of code into reusable files. They eliminate global namespace pollution, ensure maintainable dependency graphs, and enable dead-code elimination (tree shaking).

# Front-End Developer Interview Questions: React

1. **What is React, and how does it differ from traditional JavaScript frameworks?**
   * React is a component-driven UI library (not a full-featured framework) focusing on the view layer.
   * Uses declarative code syntax, unidirectional data flow, and a virtual DOM, whereas traditional frameworks often rely on two-way data binding and direct DOM manipulation.

2. **What are React hooks, and why are they used?**
   * Functions allowing functional components to hook into React state, lifecycle updates, and side effects without writing legacy class components (e.g., `useState`, `useEffect`, `useReducer`).

3. **What is the virtual DOM, and how does React use it?**
   * A lightweight in-memory JSON representation of the actual DOM. React generates new virtual tree snapshots upon state updates, runs a reconciliation ("diffing") algorithm against previous snapshots, and batches target changes efficiently to minimize costly browser paints.

4. **What are React props, and how are they different from state?**
   * **Props:** Read-only inputs passed from parent components down to child components (immutable context).
   * **State:** Local component instance variables managed internally that trigger component re-renders when mutated via state updater functions.

5. **What is JSX, and how does it work in React?**
   * A syntax extension for JS that lets developers write HTML-like markup directly inside script files. Tooling compilers like Babel transpile JSX elements into `React.createElement()` function calls.

6. **Explain the difference between controlled and uncontrolled components in React.**
   * **Controlled:** Component UI state and input value are driven entirely by explicit React state (`value` property attached to `onChange` dispatcher).
   * **Uncontrolled:** Component input value relies directly on native DOM node management, accessed via React references (`useRef`).

7. **What is React’s Context API, and when would you use it?**
   * Native mechanism for broad state broadcasting through component hierarchies without manually passing props down through nested children ("prop-drilling"). Ideal for low-frequency global values like theme colors or authenticated user details.

8. **What is the purpose of `key` props in React, and why are they important?**
   * Unique identifiers used by the diffing engine to track list item insertions, mutations, or deletions. Omitting stable key props forces inefficient full list re-renders and causes state leakage across sibling elements.

9. **What are React lifecycle methods? Provide examples of their use cases.**
   * Hooks or methods executing at specific phases of a component (Mounting, Updating, Unmounting). In modern React, `useEffect` abstracts lifecycle phases:
     ```javascript
     // Mount/Unmount equivalent
     useEffect(() => {
       const sub = subscribe();
       return () => sub.unsubscribe(); // Unmount cleanup
     }, []);
     ```

10. **How would you handle performance optimization in a large React application?**
    * Implement code-splitting using `React.lazy` and `Suspense`.
    * Prevent expensive recalculations using `useMemo` and standard function recreation using `useCallback`.
    * Wrap structural tree pure components in `React.memo`.
    * Virtualize long dynamic list renders using libraries like `react-window`.

# Front-End Developer Interview Questions: Angular

1. **What is Angular, and how does it differ from other frontend frameworks?**
   * A full-fledged, opinionated TypeScript framework provided out-of-the-box with routing, HTTP clients, form management, and testing utilities. Uses dependency injection and strict modular patterns, contrasting with component libraries like React.

2. **What is the Angular lifecycle, and why is it important?**
   * Sequential events tracking component life from creation through deletion. Key hooks include:
     * `ngOnInit`: Executes initialization parameters after data-bound inputs resolve.
     * `ngOnChanges`: Fires whenever input binding values shift.
     * `ngOnDestroy`: Handles cleanup routines prior to component disposal.

3. **Explain the difference between `@Input()` and `@Output()` decorators in Angular.**
   * **`@Input()`:** Decorator marking a property as callable by a parent component to pass data downstream.
   * **`@Output()`:** Decorator binding an `EventEmitter` instance to pass data upstream to parents via event handling.

4. **What is Angular’s dependency injection system, and how does it work?**
   * A structural pattern where class dependencies (e.g., services) are instantiated and supplied by Angular's runtime framework rather than explicitly instantiated manually inside target components. Uses `@Injectable()` decorators.

5. **What is the purpose of Angular modules, and how are they structured?**
   * **NgModule:** Contextual containers organizing cohesive application blocks. Defined by `@NgModule`:
     * `declarations`: Components, directives, and pipes belonging to the module.
     * `imports`: External modules required by templates within this module.
     * `providers`: Services available for dependency injection.
     * `exports`: Declarations exposed to importing modules.

6. **What are Angular directives, and what are the differences between structural and attribute directives?**
   * **Structural Directives (`*ngIf`, `*ngFor`):** Alter actual layout DOM structure by dynamically instantiating or destroying HTML elements.
   * **Attribute Directives (`ngClass`, `ngStyle`):** Change appearance, class properties, or behaviors of existing DOM elements without altering tree architecture.

7. **What are Angular pipes, and when would you use them?**
   * Pure dynamic functions declared inside templates (`|`) to format output parameters (e.g., currency, dates, string transformations) without mutating underlying raw variable models.

8. **How does Angular handle forms, and what is the difference between template-driven and reactive forms?**
   * **Template-Driven:** Simple forms defined entirely within HTML markup using implicit directives like `ngModel`.
   * **Reactive Forms:** Programmatic, explicit form models configured in TypeScript using `FormGroup` and `FormControl`. Offers predictable immutable state streams and synchronous dynamic validations.

9. **What is the Angular Router, and how does it handle navigation?**
   * Enables single-page navigation across states by mapping browser paths to target component views via structural array definitions. Intercepts navigation using Route Guards (`CanActivate`).

10. **What strategies would you use to optimize an Angular application’s performance?**
    * Switch component strategies to `ChangeDetectionStrategy.OnPush`.
    * Configure lazy-loaded feature modules.
    * Utilize `trackBy` functions with structural `*ngFor` loops.
    * Build projects using Ahead-of-Time (AoT) compilation.

const twoSum = (nums, target) => {
  const map = new Map();
  for (let i = 0; i < nums.length; i++) {
    const complement = target - nums[i];
    if (map.has(complement)) {
      return [map.get(complement), i];
    }
    map.set(nums[i], i);
  }
  return [];
};
